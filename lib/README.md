## 寸法を検証した記録

**取り込む前に、規格値と照合した。** フットプリントを間違えると基板が
まるごと無駄になるので、他人のライブラリでも鵜呑みにしない。

`SW_Hotswap_Kailh_MX_1.00u` のパッド（キー中心からの相対位置）:

| パッド | 位置 | 規格値 | 判定 |
|---|---|---|---|
| スイッチピン穴 1 | (−3.810, −2.540) φ3.05 | MX 標準 (−3.81, 2.54) | ✅ |
| スイッチピン穴 2 | (2.540, −5.080) φ3.05 | MX 標準 (2.54, 5.08) | ✅ |
| 中央ポスト | (0, 0) φ4 | MX 標準 φ4 | ✅ |
| 位置決めポスト ×2 | (±5.080, 0) φ1.75 | MX 標準 φ1.75 | ✅ |
| ソケット端子 1 | (−7.085, −2.540) **B.Cu** | Kailh CPG151101S11 | ✅ |
| ソケット端子 2 | (5.842, −5.080) **B.Cu** | 同上 | ✅ |

Y の符号が反転しているのは KiCad が Y 下向きだから。

**ソケットが裏面（B.Cu）にある**ことも確認した。ケース設計の前提
（基板下へ出る。データシート PG151101S11 で 1.80mm・ボス込み 3.05mm）と一致する。

スタビライザーの間隔（±11.938 / ±19.05mm）も Cherry の規格
（0.47 / 0.75 インチ）と一致した。**この値はプレートと共有する必要があるので
`foundry/mech.py` に置いてある。** 基板側とプレート側で別々に持つと
食い違う（以前ネジボスの位置で実際にやらかした）。

### SW_Kailh_Choc_V1（Choc V1・直付け）

出典: `perigoso/keyswitch-kicad-library`（`main` ブランチ、2026-09-23 に取得。
この repo は `kiswitch/kiswitch` の旧名で、同じプロジェクトの旧配布点として
アーカイブされている。MIT ／ CC-BY-SA 4.0 のデュアルライセンスは同じ）。
`SW_Kailh_Choc_V1`（幅の付かない名前）を使う。**幅つき（`_1.00u` など）は
使わない**: キャップ外形（Dwgs.User）が Choc の 18×17mm ピッチで描かれて
おり、MX の 19.05mm ピッチのグリッドに並べると嘘になる。パッドの位置・
穴は全幅で同一（2026-09-23 に 1.00u と 2.25u をダウンロードして diff し、
パッドの行が一致することを確認済み）。

Kailh の図面 CPG135001D01（keyboardio/keyswitch_documentation に保存された
PDF、`PG1350 Keyboard Switch` 料号 CPG135001D01-16）の 1 ページ目、
右下の "P.C.B Layout (Pattern Side)" の図と `tests/test_choc.py` で照合：

| 項目 | 図面の値 | フットプリントの値 | 判定 |
|---|---|---|---|
| 端子穴 ×2（φ1.20 相当） | 図の生値 (−5.90, 0)・(−3.80, −5.00) | (0,−5.9)・(5,−3.8) | ✅（鏡像＋回転で一致。下記） |
| 中心穴 | φ3.40、図の生値 (0, 0) | (0,0) φ3.45 | ✅（余裕あり） |
| ボス ×2 | φ1.90、図の生値 (0, ±5.5) | (±5.5, 0) φ1.9 | ✅ |
| プレート開口 | 13.80 | `mech.CHOC_V1.cutout` 13.8 | ✅ |

図の "P.C.B Layout (Pattern Side)" は半田面（部品を基板に取り付けた
とき下から見る面）から見た図で Y は図の上向きが正。KiCad のフット
プリントは部品側（上から見た向き）で Y は下向きが正。**「X を反転
（半田面→部品側）」と「Y を反転（上向き→下向き）」はどちらも単独
では鏡映（実物と左右が逆になる操作）だが、2 回続けてかけると鏡映が
打ち消し合って普通の回転になり、実物のハンド性（鏡像でないこと）が
保たれる。** X の反転を飛ばして Y の反転だけをかけると鏡映が 1 回
だけ残り、結果は実物の鏡像になる（実物のピンがフットプリントに
刺さらない形。`tests/test_choc.py` の `test_the_checker_notices_a_mirrored_footprint`
が防いでいるのはこれ）。

さらに +90° 要る。これは図面のシート内の視点どうしの違いではない
（このシートの図はどれも同じ向きで描かれている）。実物のスイッチが
キーボードの中でどちらを向いて座るか、という向きの差である。
根拠: シート 1 ページ目左端の上面視の図では、キーキャップの軸受け
スロット（3.00 × 1.20・間隔 5.70）が**縦に**並んでいるが、Choc の
キーキャップの 2 本のポストは**横に**並ぶ。kiswitch・Keebio の 2 つの
独立したライブラリもどちらもボスを左右（横）に置いている。図の並び
（縦）と実物の座り方（横）の差が +90° になる。

したがって図の生座標から KiCad の座標へは

1. **X を反転する**
2. **+90°（反時計回り）回転する**: `(x, y) → (−y, x)`
3. **Y を反転する**

の 3 手順が要る（`tests/test_choc.py` の `_to_kicad()`）。端子 A の
生値 (−5.90, 0) をこの順で変換すると (0, −5.90) になり、フットプリント
の端子 1 `(0, −5.9)` と一致する。ボスの生値 (0, ±5.5) も同じ変換で
`(∓5.5, 0)` になり、フットプリントの `(±5.5, 0)` と一致する。この結果は
2 つの独立した上流ライブラリ（kiswitch・Keebio、いずれも同じ
`(0,−5.9)` / `(5,−3.8)`）とも一致しており、フットプリントのハンド性
（鏡像でないこと）を裏付ける。`tests/test_choc.py` は鏡像のまま
（X の反転を飛ばした）偽のフットプリントでも落ちることを確認している。
