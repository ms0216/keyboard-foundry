HHKB 分割機（2026-08-04〜09-23）で**実際に起きた**ことだけを、規則の形にしたもの。
出典の番号（#N・日付）は HHKB のリポジトリ（`../2608042258_HHKB_devided`）の
`docs/hardware/open-gaps.md` と各記録を指す。

CLAUDE.md の「検証の作法」はここの要約。**迷ったらここの具体例を読む**——規則だけだと
「自分の件は違う」と思えてしまうが、具体例を読むと同じ形だと分かる。

## I. 作業の進め方

| 起きたこと | 規則 |
|---|---|
| 別セッションが全部を `git add -A` で拾い、作業途中のファイルが無関係なコミットに紛れた | **触ったファイルだけ名指しで stage。**`git diff --cached` を読む |
| 名指しでも、そのファイルに別セッションが書きかけた呼び出しが混ざり、定義側が入らず main が ImportError | 自分が書いていない行が混ざっていないか読む |
| push は成功して見えて、別セッションが切り替えた別ブランチに乗っていた（2 回） | commit/push の直前に `git status -sb` の 1 行目を**別の呼び出しで**読む |
| 検査の実行中に編集して偽の赤・偽の緑（2 回）。mutate が 6 時間後に並行の編集を上書き | 検査中は検査が読むファイルを編集しない |
| 長い検査の間、何もせず待っていた（1 日に 3 回指摘） | 読み取り専用の監査・外部の裏取り・次の編集の準備を並行する |
| 「自分より前から赤」を「環境の問題・範囲外」で止めた。実際は真の指摘と、直し方が既にある問題だった | 切り分けたあと必ず原因まで降りる。常駐した赤は新しい赤を隠す |
| 理解の確認（「合っている」）を着手の許可と取り違えた | 理解の確認と実行の許可は別 |
| 合意の外の条件を実装側が黙って足した | 合意の外に出るなら、実装せずに測定つきで提示する |
| 自分の探索スクリプトが 0 件を返したのを理由に、利用者の指示を捨てた（3 回） | 利用者の指示は固定し、成立させる方法を探す。疑うのは自分の道具 |
| 新しい経路に乗り換えたあと、赤を「たぶん既知」と流して先へ進んだ | **差分を分類して数える。**合格は「差が意図したものだけ」（差分ゼロではない） |
| 検査を回さず「刷ってよい」と言い、棚の無い上シェルを刷らせた | 印刷を渡すときは「回した検査／回していない検査」を明示し、判断を返す |
| 残作業を列挙して振り分けを利用者に頼んだ | スコープ内ならやる。外なら記録があることを確かめて任せる |

## K. 直せない側に倒した（寸法の非対称）

**規則:** 発注後に直せない寸法（基板）は、直せる側に倒す。きつい・小さい側は後から削る・広げる・撓めることで
直せるが、ゆるい・大きい側は直せない。ゆるい側を選ぶのは、ゆるくても害が無いと示せたときだけ。
後から広げる前提の穴の周りには信号を通さない。

| 起きたこと | 規則 |
|---|---|
| CCKB（2026-09-25〜26）: Choc V2 のねじ留めスタビの穴を、出典 2 つ（販売者が「参考程度」と書く仕入れ先の図・支点 24.0 と、販売者が実物を測った足跡・支点 23.8）の**和**で開けた。ねじの穴は長円 3.2 × 3.4、爪の穴は 4.2 × 4.4。「どちらの実物でも入る」を合格にしていた | 和は「入る」だけを見て、**ゆるさの害**を見ていない。ねじ留めのスタビは、締める前に穴の遊びの分だけ動く（監査 E 重要 3: x ±0.2）。キャップのスタビの受け口の隙は片側 0.05〜0.075 で、ずれは発注後に直せない。しかも長円は JLC の「長さ ≧ 幅 × 2」を満たさず作れなかった（C 重要 1） |
| 直し方: 実物を測った方（足跡）を正にして、**丸 φ3.0（ねじ）・φ4.0（爪）**を支点 ±11.9 に開け、穴の中心から半径 2.6 の中は GND のベタ以外の銅（線・ビア・ほかの網）を置かない。穴がきつければ手でリーマ・やすりで広げられ、広げても信号に当たらない | **きつい側を選んだら、直す手段（広げる余地）まで設計に入れる。**直せない側（ゆるい穴）を選ぶなら、ゆるくても害が無いことを数で示す（例: 床の止まり穴は刷り直せ、大きくても当たらないだけ） |
