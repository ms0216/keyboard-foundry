# 基板（KiCad 10・JLCPCB）

foundry が自動でやるのは**キーマトリクスの未配線の板まで**（`tools/kb <機種> pcb`）。
そこから先（MCU・電源・配線・GND・発注）は機種ごとに違うので、HHKB の手順と罠を
ここに残す。参照実装は HHKB の `tools/{gen_pcb,finalize_pcb,gnd_fanout,autoroute,
gen_daughterboard,export_matrix_routing}.py` と `docs/hardware/pcb-routing-handover.md`。

## 流れ

```
spec.py + layout.json
   └ tools/kb x pcb          → projects/x/pcb/unrouted/x_<部品>.kicad_pcb（キー・ダイオード・スタビ・穴・規則）
       └ pcb_extra.py の place()  で MCU・コネクタ・電源を足す
   └ KiCad で配線（HHKB は最終的に手で引いた。自動配線は下の注意）
   └ 配線した板を projects/x/pcb/x_<部品>.kicad_pcb に置く（ここからは板が正本）
   └ GND のビア（fanout → fence → ring → stitch → islands の順）
   └ tools/kb x fab-fields   → LCSC・面・BOM 除外を焼く
   └ tools/kb x drc          → 記録（指紋つき）。警告も数える
   └ tools/kb x render       → **絵を見る**（hook が毎回出す）
   └ fab-checklist.md を上から
```

## 規則（foundry が板と .kicad_pro の両方に書く）

- **KiCad 既定の規則で DRC 0 でも JLC で作れるとは限らない。**線幅・間隔 0.127、
  ビア φ0.45/0.2 以上、アニュラ 0.13、穴間 0.45、外形まで 0.3、シルク 0.15
- **kicad-cli の DRC は隣の `.kicad_pro` から規則を読む。**板だけを別の場所で回すと
  別物に見える。規則を直したらプロジェクトファイルも同期する（pcb.py がやる）
- 自動配線器はネットクラスしか見ない。実際に引く寸法（0.2 / ビア 0.6/0.3）を明示する。
  **ネットクラスは Recompute しないと割り当てが効かない**
- 電源の太さ: 0.5mm ピッチの FFC はパッド幅 0.30・隙間 0.20。0.3mm の線は**隣のパッドの間を
  抜けられない**（パッドの幅と隙間を取り違えた）→ 0.2
- ビア φ0.5/0.3 はアニュラ 0.10 で規則割れ → φ0.6/0.3
- **NPTH の縁から外形まで 1.0mm 以上**（pcb.py が生成時に止める）。スペースのスタビを
  素の向きで置くと 0.381mm（外形公差 ±0.2 で 0.18mm の橋）→ ワイヤ奥（180°）で 2.14mm
- Kailh ホットスワップは内部の穴間が 0.4398（JLC 0.45）。キーの数だけ `hole_to_hole` 警告が出る。
  部品の寸法なので直せず、**穴は残す**（5 ピン用を 3 ピン用にはできるが逆はできない）。
  JLC は製造前に連絡してくる（HHKB #50）
- シルク最小 0.15（KiCad 標準 0.12 はかすれる）。**全部品を置いてから太らせる**。
  生成器が 2 本あると片方だけ直りがち
- 他社の商標を板に刷らない（HHKB は "SSKB"）。左右・機種の識別は必ず刷る

## 層と GND

- **層は実際の配線を数えてから決める。**HHKB は 4 層で始め、信号が 2 層に収まっていた
  （決定記録が実態に追いつかず、根拠として残った）→ 2 層・両面 GND ベタ
- 部品は片面（裏）に集める。JLC の片面実装は安く、Economic PCBA は片面限定
- GND ベタは**配線を載せたあとに塗り直す**（`ZONE_FILLER.Fill`）。「足した」と「塗られた」は別
- 健全性は**面積**で見る。KiCad は切り離された島を黙って消すので、多角形の数は 1 のまま
  面積だけ半分になる。浮いた GND の銅は 2.4GHz でアンテナになりうる → 繋ぐか消すかで 0 にする
- ビアの順: **fanout（全 GND パッド）→ fence（長い配線の脇・最も効く）→ ring（禁止域の縁）
  → stitch（格子）→ islands（離島を繋ぎ戻す）**。格子を先に打つとフェンスの場所を取られる
- SMD の GND パッドは**同じ層のスタブ→ビア**で繋ぐ。ベタが偶然被っているだけの接続に頼らない
- アンテナの下は [rf-antenna.md](rf-antenna.md)
- 取付穴は GND に繋がない（樹脂ケースでは意味が無い）

## 配置

- 部品は**段と段の間の帯**（9.25mm × 全幅）に置く。帯の中心はソケットの占有が非対称
  （−2.6〜+7.2mm）なぶんずらす
- 部品は原点ではなく**コートヤードの中心**で帯に合わせる（FFC は原点が 0.95mm ずれていた）
- 取付穴は **5 条件を同時に**: 縁から 1.0 以上・キーとプレート開口・部品・コートヤード・配線
  （別々に確かめて 3 往復した）。穴の目的関数に後で引く配線を入れる
- 名札（リファレンス）はキーの枠を避ける向きに回す（消さない）
- 板のテキスト（キー名）は部品を動かしても付いてこない
- 裏面にコネクタを置くとピンの並びが鏡像になる。**コネクタは面だけでなく口の向きと
  口から口までの経路を追う**（口の向きが `Flip()` の副作用で誰も決めないまま決まっていた）
- ケースの幅を変えると、内壁基準で置いたコネクタが動いて凍結した配線が切れる（9 ネット）

## 配線

- 決まりきった局所配線（スイッチ→ダイオードの L 字、行のバス）は自分で引いてよい。
  それ以外を手書きのルータでやらない（衝突判定が無く任意のネットを短絡させた）
- Freerouting（2.3.0・`-de dsn -do ses -mp N`・OpenJDK）: 決めた配線は `(type protect)` で渡す。
  **効くのは via_costs**（0 は逆効果・2 が良かった）。`autoroute_settings` を DSN に書くと
  壊れる。クリアランスの余裕 20µm（15 は丸めで違反・25 は未配線）。ログの違反数ではなく
  KiCad の DRC で判定。SES 取り込みは既存の配線を消す
- HHKB の最終形は**利用者が KiCad で手で引いたものを JSON に写して再現する**方式
  （`export_matrix_routing.py`）。**配線を加工する判定を書くと壊れる**——KiCad は端点どうしの
  接触しか数えないが、電気は線の途中でも繋がる。道具は写すだけにする
- CCKB（2026-09-24）で分かったこと（`projects/cckb/tools/route_pcb.py`・`docs/pcb-routing-handover.md`）:
  - Freerouting 2.3.0 は **`(autoroute_settings)` があるとネットを 1 本も見ない**ことがある（HHKB の子基板と
    CCKB の本体の 2 回）。ログの「0 unrouted items」「no SMD pins」が合図
  - 自分で引いた線を `fix` で渡しても接続と見ない。**線は protect、ネットは「駆動側」と「最寄りのパッド」
    の 2 ピンに絞る**と、最後の 1 本だけを引かせられる
  - DSN からパッドを消すと、そこを線が通る（短絡）。消すなら禁止域で覆う
  - 外形・切り抜きはネットクラスの間隔でしか避けない（JLC の 0.3 を割る）→ 縁に配線禁止の帯
  - 同じ入力なら同じ結果だが、小さな変化で未配線が 0 ↔ 2 に揺れる → 余裕を決まった順に試して記録
  - **KiCad 10 は読み込み時に線のネットを繋がりから付け直す**。「ネット名を書き換えて DRC が気づくか」
    という壊し方は効かない（線を太らせる・動かす）
  - ビアを置く自前の判定は、**穴の中（切り抜きの真ん中）・長いスタブ・同じネットのビアどうしの穴間**を
    落としやすい（3 つとも踏んだ）。外形は多角形の内外で、穴間はネットに関係なく見る
- **DRC 0 は配線が良いことを意味しない。**層ごとの本数と長さ・ビア数・GND の島・遠回りの比
  （> 3 に注意）を数字で出し、絵で見る

## 回路図と結線

- 順序は **回路図 → ERC → アートワーク → DRC**。そのうえで回路図と板の netlist を突き合わせる
- **ピン名とパッド番号は別物**（foundry/pinmap.py）。引けなければ落とす。握り潰すと
  ネットの無いパッドが DRC 0・未配線 0 のまま残る（HHKB で 595 が丸ごと消えていた）
- 回路図は宣言（データ）から生成し、電気的種別を付ける（無いと ERC は飾り）。
  kiutils 1.4.8 の書く回路図は KiCad 10 で読めない
- テストポイントは部品を足さず、既存ビアのテンティングを外すか配線上にマスクの窓を開ける。
  部品本体からこて先 0.6mm・隣の銅 0.5mm は除外。GND を隣に

## 発注（Fabrication Toolkit）

- 実際に発注する道具を本番の板に通して出力を読む（fab-checklist §0b）
- **実装面はパッドの層で決める**（`IsFlipped` は置いた面。ソケットは F.Cu に置いてパッドが B.Cu）。
  `pad.GetLayerName()` は裏のパッドでも F.Cu を返す → `IsOnLayer(B_Cu)`
- CPL の回転は KiCad と JLC で一致しない。`-t` を付けないと TSSOP の補正が入らない。
  配置プレビューの「+」は Pin 1 ではなく**アノード**（SOD-123）
- 2 層の板に内層のガーバーを混ぜると 4 層で作られる
- 子基板だけ先行発注すると $25〜35・2〜3 週。手戻りを小さな板に閉じ込めるなら界面を凍結して検査で守る

## KiCad の Python・ファイル

- pcbnew は KiCad 同梱の Python（3.9）にしか無い。数値は pcbnew に依存しないモジュールに置き、
  検査は venv から S 式のテキストとして読む（tests/test_meta.py が依存を見張る）
- `Flip()` は `board.Add` の後で（前だと segfault）
- `.kicad_pcb` は保存のたびに UUID と並び順が変わる → **バイト列の sha256 で比べない。**
  配置・結線・外形だけの指紋（foundry/boardhash.py）
- KiCad 10 はネットを `(net "COL0")` と名前で書く。番号前提の正規表現は 0 件でも黙って通る
- パッドを正規表現の窓で探すと、ネットの無いパッド（NPTH）から**隣のパッドのネットへ滑る**
  → 括弧の対応で切り出す（foundry/board_dump.py）
- KiCad は見つからない 3D モデルを**警告なしに飛ばす**。STEP に出た数を数える。
  モデルの在処は `KICAD10_3DMODEL_DIR` / `KICAD6_3RD_PARTY`。CI の KiCad は手元と同じ版に
  （9.0 は 10 の板を読めず終了コード 3。stderr を捨てていて気づかなかった）
- 1:1 印刷は `kicad-cli pcb export pdf --layers Edge.Cuts,...`。実寸は Edge.Cuts だけで測る
  （F.Fab の文字で外形が大きく見える）。画像化は pdf → `pdftoppm`（qlmanage は縦横比が壊れる）
- 裏面の極性は頭の中で鏡像変換しない。ネット名をシルクに焼いて同じ絵で読む
