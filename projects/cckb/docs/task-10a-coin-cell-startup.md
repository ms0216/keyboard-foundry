# Task 10a — CR1632 で起動・スリープ復帰できるか

**所要時間の目安:** 配線 15 分 ＋ 主の測定 約 45 分 ＋ 実電池の突き合わせ 15 分 ＋ 紙の判定 10 分 ＝ **約 1.5 時間**
（任意の打ち止めの確かめ §8 は ＋15 分）

**買う物は無い。**可変電源・HHKB の試作の XIAO と 100Ω・手持ちの CR1632 と 1MΩ で足りる（§3）。

> 2026-09-25 に作り直した（前の版は「CR1632 → 直列抵抗 → ダイオード 2 種 → XIAO」を常温と冷蔵で各 10 回）。
> 分からないのは **XIAO＋ZMK が起動に要る電圧**で、それは可変電源で直接測れる、と利用者が指摘した。
> 電池とダイオードはデータシートで紙の上に載せる。前の版の中身は git の履歴にある。

## 1. なぜやるか

**CR1632 は内部抵抗が高い（新品で約 26Ω）。その抵抗越しに ZMK が起動できるかは、データシートからは分からない。**
電池の側（電圧と内部抵抗）とダイオードの側（順電圧）はデータシートに値がある。**無いのは XIAO＋ZMK の側**
——「直列に R が入ったとき、何 V あれば毎回起動するか」——だけ。そこだけを可変電源で測り、残りは紙の上で組む。

HHKB 分割機は同じ XIAO を可変電源と直列抵抗で測った（`../2608042258_HHKB_devided/docs/hardware/task-c4-c5-power.md`
§7「★★ 実測（2026-08-11・可変電源）」②）。**25Ω で 2.42V では確率的、2.60〜2.70V で確実**、10Ω で 2.15〜2.25V。
ただしこれは親（セントラル。子を探し続ける）のファームで、行列と 1N5819 が入り、電圧はダイオードの手前で読んでいる。
CCKB は一体型で広告だけなので軽いはずだが、HHKB の数字をそのまま当てると新品の常温でも**ぎりぎり**になる（§6）。
だから測る。

| # | 確認対象 | 不成立だと |
|---|---|---|
| 1 | 直列抵抗 R ごとに、R 越しに XIAO の 3V3 へ入れて**毎回起動する最低の電源の電圧** V_boot(R) を測る（表を作る） | 紙の判定ができない |
| 2 | 新品の CR1632 を直に当てても、抵抗の模型から予想したとおりに起動する | 模型が甘い（電池の方が悪い）。判定に余裕を足す |
| 3 | 紙の上で、電池の状態（新品〜末期・常温と −10℃）ごとに「電池の電圧 − ダイオード ≧ V_boot(内部抵抗)」が成り立つか | 成り立たない所まで電池が使えない |

**1 が本命。**起動は 1 回点いても合格にしない（毎回点くかを見る。境目の近くでは確率的になる——HHKB で実際に見た）。
スリープからの復帰は起動と同じ手順なので、起動で代用する（`docs/knowledge/power.md`）。

このタスクが確認しないこと: 基板が届いたあとの実機（595・行列込み）での再現（計画 3）、キー入力そのもの、
USB 給電中のダイオードの逆漏れ（基板の D_PWR で試作のときに測る・open-gaps A1）。

## 2. 構成（本番と何が違うか・なぜ変数を 1 つに絞るか）

```
主の測定     可変電源 ─ 直列抵抗 R ─ XIAO の 3V3        （ダイオードなし・BAT は空き・USB は抜く）
                                  └ XIAO の GND ─ 可変電源の −
突き合わせ   CR1632  ─（R_ext）─ XIAO の 3V3           （同じ XIAO・同じファーム）
本番         CR1632 ─ 電源スイッチ ─ BAT46W（D_PWR）─ XIAO の 3V3
```

- **ダイオードを入れない。**ダイオードの順電圧はデータシートの**保証値**で紙の上に載せる（§6）。実物を 1 個測っても
  典型値が 1 つ分かるだけで、保証値の代わりにならない。前の版は基板と同じ JSCJ の SOD-123 を LCSC から買って
  両方測る段取りだったが、要らなくなった（open-gaps O12）
- **電池の代わりに可変電源＋直列抵抗。**電源の電圧が電池の電圧、直列抵抗が電池の内部抵抗の代わり。
  電源は内部抵抗がほぼ 0 なので、**R だけが変数**になる。冷やす試験もしない: 冷えた電池は「電圧が下がり内部抵抗が
  上がる」だけで、それはデータシートの値で表の別の行を読むことになる（§6）
- **XIAO 単体**（キー・74LVC595 なし）。ファームの起動と BLE の広告だけを見る。キーや 595 の不具合を電源の不具合と
  取り違えない
- **電池電圧を読む分圧（1MΩ＋1MΩ → D0）は入れない。**要らない理由: 判定は起動から 30 秒以内に済み、
  「打ち止めを割ったら自分から止まる」処理はそれより後にしか動かない。`firmware/src/low_battery_off.c` の
  `low_battery_init()` は最初の判定を `CONFIG_ZMK_BATTERY_REPORT_INTERVAL + 5` 秒後に置き（`cckb.conf` は間隔を
  設定していないので ZMK の既定 60 秒〔ZMK main の `app/Kconfig.defaults`・2026-09-25 に読んだ〕→ **65 秒後**）、止まるのは下回りが
  `CONFIG_FOUNDRY_LOW_BATTERY_SOFT_OFF_SAMPLES` 回（既定 2・`firmware/Kconfig`）続いたとき、つまり**早くて 125 秒後**。
  D0 が浮いていても、65 秒より前には何も起きない。**だから 1 回の試しは電源を入れてから 60 秒以内に切る**

**BAT 端子には絶対に繋がない**（`docs/knowledge/power.md`。BAT はリポ充電回路に直結していて、USB を挿すと
一次電池を充電しようとして液漏れ・破裂の危険がある）。

**USB は挿さない**（焼くときと §5 の 1 の対照を除く）。USB を挿すと 3V3 が USB 側から持ち上がり、電源の側の
試験にならない。**USB を挿すときは、先に可変電源（か電池）を外す。**

## 4. 配線

| # | 挿すもの | 場所 |
|---|---|---|
| 1 | XIAO nRF52840 | ブレッドボードの中央。USB は端にはみ出す向き |
| 2 | 直列抵抗 R（0Ω はジャンパ） | 可変電源の＋ → XIAO の **3V3** |
| 3 | ジャンパ（GND） | 可変電源の− → XIAO の **GND** |
| 4 | 可変電源 | **いちばん最後に**、出力を合わせてから挿す（下の注意） |

**BAT 端子には何もつながないこと**を、電源を挿す前に目で確かめる。D0 も空きでよい（§2）。

> **⚠️ 可変電源は、つなぐ前に出力を合わせる。**3V3 ピンに直に入るので、nRF52840 の絶対最大定格 3.9V を超えると
> 壊れる（HHKB task-c4-c5 §7「可変電源は、つなぐ前に必ず出力を合わせる」）。出力をどこにもつながずに 3.00V に合わせ、
> 一度切って入れ直してもう一度 3.00V が出ることをテスターで見てから挿す。**この試験では 3.30V より上にしない。**

### 通電する前に、これだけは見る

| 見るもの | 期待 | 意味 |
|---|---|---|
| 3V3 と GND の導通 | 鳴らない | 鳴ったら短絡。電源を挿してはいけない |
| BAT 端子 | 何もつながっていない | つなぐと液漏れ・破裂の危険（電池のとき） |
| 直列抵抗の値（テスターの抵抗レンジ・挿す前に） | 狙いの値 ±10%。**実測値を記録の表に書く** | 100Ω の並列は間違えやすい。紙の判定は実測値で読む |
| USB | 挿さっていない | 挿さっていると電源の側の試験にならない |

## 5. 手順

**焼くファーム**: `cckb-xiao_ble__zmk-zmk.uf2`。**2026-09-25 以降のビルド**（打ち止めの判定を毎回測り直す直し
d48249a が入ったもの）。入手先: <https://github.com/ms0216/keyboard-foundry> の Actions →「Build ZMK firmware」の
成功した実行 → Artifacts の `firmware`。例: 実行 36023373707（コミット 768c526・2026-09-25 00:52 日本時間）は
d48249a を含む。**焼く前に、どの実行・どのコミットのものかを控える**（HHKB の教訓 C2）。
XIAO をブートローダーモードにして（リセットボタン 2 回押し）、ドライブとして見えたらこのファイルをコピーする。

1. **対照（USB）**: 焼いた直後、USB のまま nRF Connect に `CCKB` が出るのを見る。出たら **USB を抜く**
   （道具とファームが生きていることを先に見せる。ここで出なければ電源の試験に進まない）
2. **主の測定**: R ＝ 0・25・50・75・100Ω の順に、それぞれ:
   1. R を差し替える（**電源を外してから**）。R の実測値を記録する。**最初の R ＝ 0 だけは、3.00V で 5 回試す**（対照）
   2. **粗く下る**: 電源を 3.00V から 0.05V ずつ下げ、各段で 1 回だけ起動を試す（下の「1 回の試し」）。
      **初めて失敗した段**で止める
   3. **細かく上る**: 失敗した段の 1 つ上から、各段で **5 回**試す。**5/5 だった最初の段**が V_boot(R)。
      落ちた回数も段ごとに書く（境目の幅が分かる）
   4. R ＝ 0 は 2.0V まで下げても落ちなければそこで止めてよい（「2.0V で 5/5」と書く）
3. **実電池の突き合わせ（1 回だけ）**: 新品の CR1632 で、同じ XIAO・同じファーム・**ダイオードなし**
   （主の測定と同じく 3V3 に直に。変数を電池の性質だけにするため。新品のコイン電池の開路電圧は 3.3V 前後
   ——Energizer の手引き p.5 の新品 CR2032 で 3.279V——で、nRF52840 の推奨の上限 3.6V より低い）:
   1. 電池の**開路電圧**をテスターで測って書く
   2. 電池だけ（R_ext ＝ 0）で 5 回起動を試す。**1 回目は別に書く**（長く置いた電池は最初の負荷で電圧が下がりやすい。
      Energizer の手引き p.6 Passivation）
   3. **境目の近くで 5 回**: §6 の記録の表から、V_boot(R_ext ＋ 25) ≦ 開路電圧 − 0.05V となる R_ext（0・25・50・75Ω）の
      いちばん大きいものを選ぶ（25 は新品の内部抵抗の代わり。R_ext ＝ 25 なら表の 50Ω の行を見る）。その R_ext を
      電池と XIAO の間に入れて 5 回試す。**模型の予想は 5/5**
4. **紙の判定**: §6 の式に表の値を入れる

**1 回の試し**:

- 電源（か電池）の線を挿す → スマホの nRF Connect で SCANNER を回し、**30 秒以内に `CCKB` が出たら成功**、出なければ失敗
- **60 秒までに線を抜く**（§2。65 秒後に打ち止めの判定が動き始める）
- 抜いたら **10 秒待ってから**次を挿す（XIAO のコンデンサを抜く。電源の出力を切るだけでなく線を抜く——電源の出力の
  コンデンサで電圧がゆっくり下がり、「徐々に上がる電源」を試すことになる）
- 電源の電圧は**線を抜いた状態でテスターで**合わせる（負荷をかけた状態では R の分だけ下がって見える）

### 対照実験を忘れない

ゼロは「起動していない」でも「見ていない」でも出る。**§5 の 1（USB で `CCKB` が出る）と、R ＝ 0・3.00V の 5/5 を
先に見せる。**これが無いと、落ちたときに「配線・スキャナーが悪い」のか「電圧が足りない」のか区別できない。

### 記録: V_boot(R)（可変電源の電圧。R の手前を、線を抜いた状態で合わせた値。ダイオードが無いので「XIAO の 3V3 へ R 越しに入る電源の電圧」）

| R（狙い） | R（実測） | 粗く下って初めて落ちた段 | 段ごとの成功（5 回中）| **V_boot(R)**（5/5 の最低） |
|---|---|---|---|---|
| 0Ω | | | | |
| 25Ω | | | | |
| 50Ω | | | | |
| 75Ω | | | | |
| 100Ω | | | | |

表に無い R は、隣の 2 つの行を直線でつないで読む。**起動の限界は R が大きいほど直線より悪くなる**と見込まれ
（HHKB §7: 抵抗が大きいほどコンデンサの回復が遅れる）、その場合の直線は上から押さえる側（控えめ）になる。
100Ω より上は外挿しない（「分からない」と書く）。

### 記録: 実電池の突き合わせ

| | 開路電圧 | R_ext | 模型の予想 | 成功（5 回中） | 1 回目 |
|---|---|---|---|---|---|
| 電池だけ | | 0 | 成功 | | |
| 境目の近く | （同じ） | | 成功（V_boot(R_ext＋25) ≦ 開路 − 0.05） | | — |

**境目の近くで 1 回でも落ちたら、模型は甘い。**紙の判定の V_boot をすべて「開路電圧 − V_boot(R_ext＋25)」＋0.05V
だけ高く読み替えてから判定し、Claude に返す。**落ちなければ模型のまま使う。**

なぜ突き合わせるか: 抵抗は流す時間によらず同じ値だが、電池の**見かけの内部抵抗は流す長さで変わる**。
Energizer の手引き（下の出典）は内部抵抗を 2 回のパルスの電圧差から出し、「流す電流とパルスの長さで計算の値が変わる」
（"The drain rate and pulse duration can impact the IR calculation"・p.5）と書く。CR1632 どうしで比べると、
Energizer の 2 秒のパルスの値は新品で 26Ω なのに、Panasonic の図（50% 放電・20℃）から連続で流したときの見かけの値を
出すと約 200Ω（1kΩ の負荷で 2.47V・100kΩ で 2.95V → 0.48V ÷ 2.47mA）。メーカーが違うので数字の比は目安だが、
**短いほど小さく、長く流すほど大きい**。起動のあいだ数 mA を秒の単位で引くなら、電池は抵抗の模型より悪く見えうる。
ミリ秒の山だけなら模型より良く見えうる。どちらかは測らないと分からないので、1 回だけ実物で当てる。

### 紙の判定（外の事実で）

**式**: 電池の状態を（休んでいる電圧 V_rest、内部抵抗 R_int）に写し、

```
V_rest(状態, 温度) − Vf_max(温度) ≧ V_boot(R_int(状態, 温度))
```

が成り立てば、その状態の電池で毎回起動する。V_rest は 0.19mA を流し続けたときの電圧で、本当の開路電圧より少し低い
（控えめ）。0.19mA はキーボードの平均の見込み（設計書 D4 の保守側 0.20mA）とほぼ同じ。

**電池（CR1632）の側** — Energizer CR1632 データシートの「Internal Resistance Characteristics」（21℃・背景 15kΩ＝0.19mA・
パルス 400Ω で 2 秒）を 200dpi で描いて曲線を読んだ。買うのは Panasonic（[shopping-list.md](shopping-list.md) §1）だが、
Panasonic のデータシートには放電の深さごとの内部抵抗が無いので、形は Energizer で読む（Panasonic の公称は 140mAh・
Energizer は 130mAh。Energizer の mAh のまま使うので、Panasonic ならこれより長く使える側）。
**−10℃** は Panasonic CR1632 データシートの「Operating voltage vs. load resistance（50% 放電）」から: 電圧は 100kΩ の負荷で
20℃ 2.95V → −10℃ 2.80V（**−0.15V**）、見かけの内部抵抗は 20℃ に対して 1kΩ の負荷で 1.3 倍・10kΩ で 1.8 倍
→ **大きい方の 1.8 倍**を使う（パルスの値の温度の倍率は、どちらのデータシートにも無い。推定）。

**ダイオード（D_PWR・BAT46W・JSCJ）の側** — 保証値 **Vf ≦ 0.45V @10mA（25℃）**・≦0.25V @0.1mA（データシートの
Electrical Characteristics）。順電圧は電流とともに増えるので、10mA の保証値は 10mA 以下のどの電流でも上限になる。
−10℃ の保証値は無い。典型の曲線（Forward Characteristics）は 10mA で 25℃ 約 0.31V・100℃ 約 0.23V（−1.1mV/℃）で、
これを −10℃ へ延ばすと ＋0.04V → **−10℃ は 0.49V** とする（推定）。10mA を超える山には保証値が無い
（典型は 30mA で約 0.41V）。HHKB の見立てでは起動中の平均は 2.7mA、無線の山は 6mA 級（§7・推定）で、10mA の内側と見る。
（B5819W は 1A の 0.6V しか保証が無く、低い電流の値が保証されていない。だから BAT46W で決める・open-gaps O12）

控えめの側。

**使える量**: 21℃ で成り立つ**いちばん下の行**の使った量を、起動で決まる使える量 q_max とする。

**O14（バルクコンデンサの場所を板に置くか）**: q_max が **96mAh 未満**なら「短い」。96mAh は設計書 D4 の
「使える時間は保守側（0.20mA）で約 480 時間」から（0.20mA × 480 時間 ＝ 96mAh）。短ければ、要求の 480 時間が
起動で削られるので、未実装の場所を置くかを利用者が決める（板の変更＝配置・配線・DRC・再現検査のやり直し）。
置く前に、同じ構成で XIAO の 3V3–GND に手持ちのコンデンサを 1 個足して V_boot が下がるかを 1 点だけ測ると、
効くかが分かる（HHKB では 100µF で救えなかった例がある・`docs/knowledge/power.md`）。**96mAh 以上なら置かない。**

**O12（D_PWR）**: この試験の結果によらず **BAT46W**（保証値で決まる・open-gaps O12）。

**合格したら**:

- open-gaps.md の #1 を取り消し線で閉じ、V_boot の表・突き合わせ・判定の表を書き写す（外の事実: 実測とデータシート）
- O14 を q_max で閉じる
- 打ち止め `empty-millivolts` を §8 で決める（任意の確かめは §8）

**不合格なら**（(a) か (b) が成り立たない）:

- D4（CR1632）を CR2032（新品の内部抵抗 約 10Ω・Energizer CR2032 データシート）に替える判断を利用者に返す。

- 先に、境目が確率的なら同じ R をもう 5 回測り直す（HHKB の教訓 J。他の R まで疑って全部やり直さない）

## 7. うまくいかないとき

- **USB でも `CCKB` が出ない**: 焼けていない。ブートローダーモードに入れたか、ファイル名が正しいか。
  前のペアリングが残っていて近くのパソコンに繋がっていないか（そのパソコンの Bluetooth を切る）。それでも出なければ
  `settings_reset-xiao_ble__zmk-zmk.uf2`（同じ Artifacts にある）を焼いてから焼き直す
- **USB では出るが、電源 3.00V・0Ω で出ない**: 配線を疑う。3V3 と GND を取り違えていないか、BAT に挿していないか、
  電源の電流の制限が低すぎないか（50mA にする）
- **出たあと 1〜2 分で消える**: 60 秒を過ぎても挿したままにしていないか（§2。打ち止めの判定が動く）
- **同じ段で成功と失敗が混ざる**: 境目の帯。5/5 になる段まで上がればよい（それが V_boot）

## 8. 任意: 打ち止め電圧（`empty-millivolts`）を決め、実機で止まるか確かめる（発注を止めない）

**これは発注の門ではない。**打ち止めはファームの値で、基板が届いてからでも焼き直せる。同じ配線で続けてできるので置く。
いまの `config/boards/shields/cckb/cckb.overlay` の `empty-millivolts = <2400>` は仮の値（open-gaps F2）。

**決め方（紙の上で）**: 分圧は電池の側（D_PWR の手前）で**休んでいる電池の電圧**を読む。§6 の表の q_max の行の
V_rest を 50mV 単位で**切り上げて** `empty-millivolts` にする。こうすると、次の起動が危なくなる前に止まる。
冷えると V_rest が 0.15V 下がるので、寒い所では早めに止まる（電池がまだ残っているのに替えることになる。安全な側）。

**実機で止まるか（15 分・1MΩ を 2 本）**: `low_battery_off.c` は「ビルドが通っているだけで、実機では一度も
動かしていない」（ファイルの注記）。

1. 分圧を足す: XIAO の 3V3 → 1MΩ → **D0** → 1MΩ → GND（ダイオードが無いので、3V3 ＝ 電池の側と同じ電圧を読む）
2. R ＝ 0 にする。焼いてあるファームの打ち止めを E とする（いまのファームなら 2.40V。決めた値で焼き直したならその値。
   焼き直しは Claude に頼む）。E の **＋0.10V** に合わせて挿す → **3 分待っても `CCKB` が消えない**
3. 線を抜き、E の **−0.10V** に合わせて挿す（その電圧が V_boot(0) より上であること。下なら起動しないので確かめられない）→ **約 125 秒で消える**（遅くとも 3 分）
   （65 秒後に 1 回目、その 60 秒後に 2 回目の判定。2 回続けて下回ると止まる）。消えたら線を抜いて入れ直せば戻る
4. 結果を open-gaps F2 に書く（2 が消えたら分圧の読みがずれている。3 が消えなければ止まる処理が効いていない）
