# Task 10a — CR1632 で起動・スリープ復帰できるか

**所要時間の目安:** 配線 20 分 ＋ 測定 90 分（条件が多いので余裕を見る）

> 先に用意するものを揃えてから始めること。途中で電池が足りなくなると
> 条件が揃えられない。

## 1. なぜやるか

**CR1632 は新品でも内部抵抗が高く、起動できるかは計算だけでは分からない。**

CR1632 はコイン電池の中でも容量が小さく、新品でも内部抵抗が約 25Ω ある
（Energizer CR1632 データシートの IR カーブ）。HHKB 分割機の親側（電池 2 本
直列・単3 想定）では、直列抵抗 25Ω のとき起動が**確率的**になった
（`task-c4-c5-power.md` §7「★★ 実測（2026-08-11・可変電源）」②）。
CCKB は一体型でキー数も少なく無線の負荷は軽いはずだが、**計算は実測より
楽観的だった**（同じ文書で「起動の限界は動き続ける限界より高い」と
分かった経緯そのものがそれ）。だから測る。

| # | 確認対象 | 不成立だと |
|---|---|---|
| 1 | CR1632 の内部抵抗（0〜75Ω 相当）で ZMK が起動する | 電源方式が成立しない |
| 2 | 起動を 10 回繰り返して毎回成功する（確率的でない） | 「電池切れなのか壊れたのか使用者に分からない」壊れ方になる |
| 3 | 冷えた電池（内部抵抗が上がる）でも起動する | 「寒い朝だけ点かない」になる |
| 4 | 打ち止め電圧（`empty-millivolts`）を実測で決められる | 残量表示が実態と合わない |

**2 が本命。** 1 回だけ点いても合格にしない。 このタスクが確認しないこと:
基板が届いたあとの実機での再現（計画 3 の範囲）、キー入力そのものの動作
（まだ実物で一度も試していない。基板が届いてから）、USB 給電時の挙動
（対照でのみ触れる）。

## 2. 構成（本番と何が違うか・なぜ変数を 1 つに絞るか）

**XIAO nRF52840 単体**（キー・74LVC595 なし）に、Task 7 のコミットでビルドした
`cckb-xiao_ble__zmk-zmk.uf2` を焼く。行列も 595 も無いのでファームの起動と
BLE 広告だけを見る構成になり、**電源の限界だけを切り出せる**（キーや 595 の
不具合を電源の不具合と取り違えない）。

> **この .uf2 は GitHub Actions が作る。**2026-09-23 に
> <https://github.com/ms0216/keyboard-foundry> へ push し、ビルドに成功した
> （コミット 39ee666・`cckb-xiao_ble__zmk-zmk.uf2` は 423KB。BLE が入っている大きさ）。
> 入手先: リポジトリの Actions →「Build ZMK firmware」の最新の成功した実行 →
> Artifacts の `firmware`。手元の `build/firmware/firmware/` にも同じものがある。
> **焼く前に、ファイル名と、どの実行（コミット）のものかを控える**（HHKB の
> 教訓 C2「焼いたファームがどのコミットのものか確かめる」）。

給電経路は **CR1632 → 直列抵抗 → ショットキー → XIAO の 3V3**。**ショットキーは本番の候補 2 つの
両方で測る**（2026-09-24 の 2 回目の監査・決定記録 2026-09-24-audit-fixes §S2・open-gaps O12）:
**BAT46W（LCSC C54110・既定）** と **B5819W（LCSC C8598）**。BAT46W は逆漏れが小さいが順電圧が
高いかもしれず（典型の比べ方ができない）、起動の余裕がダイオードで変わりうるため。どちらを本番に使うかは
この結果も見て利用者が決める。**足つきの 1N5819・BAT46 は代わりにならない**（2026-09-25 にデータシートで比べた・
[shopping-list.md](shopping-list.md) §4）: ST の BAT46（DO-35）は保証値は BAT46W と同じだが、典型の順電圧が 10mA で約 0.1V 高い
（ST 約 0.40V・JSCJ 約 0.30V）。1N5819 は 1A の保証値だけが同じで、接合容量が約 2 倍（ダイが違う）、基板の B5819W は試験の電流の
範囲の値がそもそも無い。だから**基板に付くのと同じ JSCJ の SOD-123 を LCSC で買って**測る（**型番で買う**）。

**電池電圧を読む分圧（1MΩ＋1MΩ → D0）も本番と同じ位置に入れる。**直列抵抗の
先・ショットキーの手前（本番の「電源スイッチの後ろ・ショットキーの手前」と同じ
位置。直列抵抗は電池の内部抵抗の代わりなので、電池の一部とみなす）。**入れないと
約 2 分で勝手に切れる。**焼くファームには「電池が打ち止めを割ったら自分から止まる」
処理（`firmware/src/low_battery_off.c`）が入っている。D0 が何にもつながって
いないと電圧が 0 付近や不定に読め、起動から 65 秒後と 125 秒後の 2 回続けて
打ち止めを下回ると止まる。それを「起動できない」と取り違えないため。
（2 回とも**その時点で測り直した値**で判定する。2026-09-25 より前のファームは ZMK の最後の測定を
読むだけで、キーの無いこの試験では起動の瞬間の 1 回を 2 回と数えていた。4 回目の監査 F 重要 1。
**焼くファームは 2026-09-25 以降のビルド**にする）

**BAT 端子には絶対に繋がない**
（`docs/knowledge/power.md`。BAT はリポ充電回路に直結していて、USB を挿すと
一次電池を充電しようとして液漏れ・破裂の危険がある）。

**USB は挿さない**（対照実験の 1 回を除く）。USB を挿すと 3V3 が USB 側から
持ち上がり、電池側をいくら下げても打ち止めの試験にならない
（`task-c4-c5-power.md` の同じ注意）。

**USB を挿すときは、先に電池を外す（本番の基板では電源スイッチを OFF）。**USB の 3.3V から
ショットキーの逆向きの漏れ電流が電池の側へ流れる（Energizer の上限 1µA。B5819W は低い逆電圧の漏れを
保証していない。BAT46W は 25℃ なら保証値で分圧の方が多く吸う。open-gaps 受け入れた差 A1・
決定記録 2026-09-24-audit-fixes §S2）。この向きと大きさは下の手順 8 で**両方のダイオードで** 1 回ずつ測る

**変数を 1 つに絞る理由**: 直列抵抗で内部抵抗を模擬し、温度（冷蔵）を
かけ合わせる。他は固定（同じ XIAO・同じファーム・同じ電池ロット）。
変数を複数同時に変えると、失敗したときにどれが効いたか切り分けられない。

## 4. 配線

図は生成器から出す想定だが、**この試験専用のブレッドボード配線図は
まだ生成していない**（HHKB の `tools/gen_breadboard_c4.py` に相当するものを
CCKB には作っていない）。挿す前に、HHKB の同等の図
（`../2608042258_HHKB_devided/docs/hardware/img/breadboard-c4.svg`）の
**電源経路の部分だけ**を参考にしてよいが、**行・列・分圧の配線はそちらには
無いので真似しない**（この試験は XIAO 単体で行列を組まない。分圧は下の表の
6・7 のとおりに挿す）。

| # | 挿すもの | 場所 |
|---|---|---|
| 1 | XIAO nRF52840 | ブレッドボードの中央。USB は端にはみ出す向き |
| 2 | 直列抵抗（条件により 0Ω ジャンパ・25Ω・50Ω・75Ω に差し替え） | 電池の＋側とショットキーの間 |
| 3 | ショットキー（BAT46W か B5819W。条件ごとに差し替える） | 抵抗の先から XIAO の 3V3 レールへ。**帯（カソード）を 3V3 側に向ける** |
| 4 | ジャンパ（3V3） | ショットキーの先 → XIAO の **3V3** ピン |
| 5 | ジャンパ（GND） | 電池の− → XIAO の **GND** ピン |
| 6 | 1MΩ（分圧の上側） | 直列抵抗とショットキーのあいだ（ショットキーの帯の**無い**側）→ XIAO の **D0** |
| 7 | 1MΩ（分圧の下側） | XIAO の **D0** → **GND** |
| 8 | CR1632（ホルダまたはワニ口） | 直列抵抗の手前に挿す。**電池はいちばん最後に入れる** |

**BAT 端子には何もつながないこと**を、電池を入れる前に目で確かめる。

### 通電する前に、これだけは見る

| 見るもの | 期待 | 意味 |
|---|---|---|
| GND とレール（3V3 側）の導通 | 鳴らない | 鳴ったら短絡。電池を入れてはいけない |
| ショットキーの帯の向き | 3V3 側 | 逆だと電圧が出ないだけ（壊れない） |
| BAT 端子 | 何もつながっていない | つなぐと液漏れ・破裂の危険 |
| D0 と GND のあいだの抵抗（テスターの抵抗レンジ・電池を入れる前） | 約 1MΩ | 分圧の下側が入っている。0 なら短絡、開放なら挿し忘れ |
| D0 とショットキーの帯の無い側のあいだ | 1MΩ 前後 | 分圧の上側が入っている。開放なら挿し忘れ |
| 直列抵抗の値（テスターの抵抗レンジで実測） | 狙いの値 ±10% | 100Ω の並列を間違えて計算しがち。挿す前に実測する |

## 5. 手順

焼くファームは **`cckb-xiao_ble__zmk-zmk.uf2`**（Task 7 のコミット。ファイル名の
コミットハッシュを控える）。XIAO をブートローダーモードにして（リセットボタン
2 回押し）、ドライブとして見えたらこのファイルをコピーする。

1. **対照実験（USB 給電）**: 電池を外し、USB でパソコンに接続。10 回、USB を
   抜き差ししてそのたびに Bluetooth 設定に `CCKB` が現れるか確認する
   （道具と手順が生きていることを先に見せる）。そのあと**起動後 3 分待っても
   切れない**ことを見る（`CCKB` が一覧に出たまま）
1b. **対照実験（電池・0Ω）**: USB を抜き、直列抵抗 0Ω で電池を入れる。`CCKB` が
   現れたら、**起動後 3 分待っても切れない**ことを見る。USB 給電中は打ち止めの
   判定が止まっているので、分圧の挿し忘れはこの電池の対照でしか分からない。
   約 2 分で消えたら分圧（§4 の 6・7）を疑う
2. 直列抵抗を条件の値に差し替える
3. 電池を入れる（挿す前に無負荷電圧をテスターで測って記録する）
4. 30 秒以内に Bluetooth 設定（またはアプリ）に `CCKB` が現れるか見る
5. 現れたら電池を一度抜いて入れ直す（＝起動をもう 1 回試す。スリープからの
   復帰も起動と同じ手順なので、これで代用する——`docs/knowledge/power.md`）
6. 同じ条件で 4〜5 を **10 回**繰り返し、成功回数を記録する
7. 常温の 0・25・50・75Ω が終わったら、電池を冷蔵庫で 2 時間冷やし、
   0・25・50Ω で同じ手順を繰り返す
7b. **ショットキーをもう一方（BAT46W ↔ B5819W）に差し替えて 2〜7 を繰り返す**。電池は同じロット。
   記録の表はダイオードごとに分ける
8. **USB 給電中の逆漏れを 1 回測る**（監査 A-1・F-3。open-gaps A1・A2）: 使い古した電池（無負荷 2.4〜2.8V）を
   直列抵抗 0Ω の代わりに**テスターの電流計（µA レンジ）越し**に入れ、USB を挿す。電池へ流れ込む向きか・
   何 µA かを記録する（1µA を超えたら「USB を挿す前に OFF」の手順が要ることの裏付け）。続けて電池を外し、
   USB を挿したまま分圧の中点（D0）の電圧をテスターで測って記録する（電池が無いのに残量が出る大きさ）。
   **終わったらすぐ USB を抜く**

### 打ち止め電圧（`empty-millivolts`）の決め方

**結論: 「起動できる内部抵抗の上限」をデータシートの図で電圧に直す。**
試験で使う電池はどれも新品なので、無負荷電圧はどの条件でも 3.0〜3.2V 前後に
なる。直列抵抗は電池の中ではなく外にあるので、無負荷電圧には出てこない。
だから「最後に 10/10 だった条件の無負荷電圧」では打ち止めが決まらない。

1. **起動できる抵抗の上限 R_ok を決める。**常温で 10/10 だった直列抵抗の
   いちばん大きい値を R_ok とする（例: 常温 50Ω が 10/10・75Ω が落ちたら R_ok = 50Ω）。
   新品の電池自身の内部抵抗（約 25Ω）は足さない。足さないぶん早めに止まる側、
   つまり控えめになる
2. **寒さのぶんを割り引く。**冷やすと内部抵抗が何倍になるかを、落ち始めた
   抵抗の比で見積もる: 倍率 k = 常温で初めて落ちた直列抵抗 ÷ 冷蔵で初めて
   落ちた直列抵抗（例: 常温 75Ω・冷蔵 50Ω で落ちたら k = 1.5）。
   使う上限は R_ok ÷ k。どちらかで一度も落ちず比が出せないときは、冷蔵で
   10/10 だった直列抵抗のいちばん大きい値をそのまま上限に使い、
   **「寒さの倍率は測れていない」と記録に書く**（このときは控えめとは言い切れない）
3. **内部抵抗の図で「残り容量」に直す。**Energizer CR1632 のデータシートの
   内部抵抗の図（放電した容量と内部抵抗）で、内部抵抗が 2 の上限に届く
   放電容量を読む
4. **放電曲線で電圧に直す。**同じデータシートの放電曲線で、3 の容量のときの
   **負荷をかけた電圧**（閉路電圧）を読む。基板の分圧は負荷がかかった状態の
   電圧を読むので、無負荷電圧ではなく閉路電圧を使う
5. その電圧を 50mV 単位で**切り上げて** `empty-millivolts` にする

この決め方は控えめ（早めに止まる）で、電池を最後まで使い切らない。
実機で電池を実際に使い切る試験（計画 3 以降）の結果で詰める。読んだ図・読んだ
値・k を記録の表の下に書き残す

**不合格なら**:
- D4（CR1632）を CR2032（容量が大きく内部抵抗が低い）に置き換える判断を
  利用者に返す。電池ホルダ BS-16-B4AK003 の寸法（open-gaps #2・O1）も
  CR2032 で成立するか合わせて見直しが要る

## 7. うまくいかないとき

- **一度も `CCKB` が現れない（USB 対照も含めて）**: ファームの書き込みを
  疑う。ブートローダーモードに入れているか、コピーしたファイル名が
  正しいか確認する
- **USB では現れるが電池では一度も現れない**: 配線を疑う。BAT 端子に
  誤って繋いでいないか、ショットキーの向きが逆になっていないかを
  電池を抜いてから確認する
- **現れたあと約 2 分で消える**: 分圧（§4 の 6・7）を疑う。D0 が浮いていると
  打ち止めを割ったと判定して自分から止まる（§2）
- **一部の条件だけ 0/10**: 電池の劣化を疑う。無負荷電圧が新品の値
  （開路 3.0〜3.2V 付近）から大きく下がっていたら電池を替えて測り直す

## 8. このタスクで確定しないこと

- 実機の基板（595・行列込み）での消費電流や打ち止め（計画 3 の範囲）
- 電池ホルダの寸法・右の角の断面（open-gaps #2・O1。計画 2 の範囲）
- ケースの組み立て（open-gaps #3）

## 9. 不成立だった場合（順に試す。飛ばさない）

1. 直列抵抗をもう一段下げた条件（例: 冷蔵 25Ω が落ちたら冷蔵 10Ω）で
   境目を狭める
2. 電池を新しいロットに替えて再現するか確かめる（個体差の切り分け）
3. それでも常温 25Ω が安定して落ちるなら、CR2032 への切り替えを
   利用者に提案する（このタスクでは決めない。D4 は利用者が決める）
