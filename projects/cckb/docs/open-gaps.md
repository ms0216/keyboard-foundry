# 実機・要求とまだ違うところ（cckb）

**差があること自体は悪くない。悪いのは、差があるのに気づけないこと。**

ここは「まだ解けていないもの」「受け入れた差」の台帳。`python -m foundry.gate cckb`
（発注の門）が下の「★ 発注をせき止めているもの」の表を読み、取り消し線の無い行が
残っていれば止める。

**書き方の約束**（HHKB で実際に起きたことが理由）:

- 節を直したら**同じ変更で一覧も直す**。一覧を見る人と節を書く人は別人になる
  （解決済みが 4 日間「未解決」で残った）。行の頭だけ「済」にして次の一手を古いまま
  残さない（2 週間残った）
- 閉じるときは**行を消さずに取り消し線**を引き、何で確かめたか（外の事実か・自分の
  生成物か）と「故意に壊して検査が落ちることを確かめた」を書く。次の一手は「無し」
- 見出しは目次のアンカーなので書き換えない。決着は見出しの直下に `> **✅ 日付 …**`
- 番号は発見順。衝突したら改番して、その旨を書く
- 「構造上できない」で閉じるときは、**その構造**を書く（前提が動いたら再評価できるように。
  HHKB #32 は前提が消えたのに 5 日間「不成立」として人を止めた）
- 解けないと結論したあとで先へ進むなら `### 承知して発注する #N` を立て、誰が・いつ・
  駄目だったとき何を作り直すかを書く。**最初に書くものではない**

| F2 | 打ち止め `empty-millivolts = 2400` は仮の値で、回路（レールの下限 ＋ B5819W の Vf）と突き合わせる検査が無い（監査 F-2） | 未。task-10a の実測で値を決めたあと、tests/test_cckb.py に HHKB の tools/test_firmware.py と同じ形の検査を足す |
| F4 | NFC のピン（P0.09/P0.10）を GPIO にする `&uicr { nfct-pins-as-gpios; };`（監査 D 重要 1 の「保険」の提案。Zephyr の xiao_ble は設定していない） | 足していない: 裁定 R3 で XIAO の裏の NFC1/NFC2 の下の表の銅を 0 にしたので、触れる相手が無い（`test_nothing_on_top_under_the_xiao`）。UICR の書き換えは UF2 のブートローダー越しに効くかを確かめていない。NFC を使わないと決めたままなら、試作で CS の波形に異常があったときの次の手 |
| F3 | sys 層の Fn+Ctrl+6 = `&bootloader`・Fn+Ctrl+7 = `&sys_reset` は分割機の左右の名残（監査 F-4） | 残す（Esc・5 と同じ動きで害は無い。HHKB 分割機の keymap と同じ並びを保つ）。理由を cckb.keymap のコメントに書いた |
